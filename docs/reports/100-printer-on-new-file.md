# 100 · 새 파일을 찍는 프린터

- 브랜치: `feat/100-printer-on-new-file`
- 근거: 사용자 요청(2026-11-02) 「office 테마에서 재밌는거 더 추가할거없을까?」 제안 표에 「그렇게 다 모두 진행해」. docs/plan/spec.md 「작업 공간 기믹」.

## 목표

개발실에 프린터를 두고, 없던 파일을 새로 만들면 프린터에서 파일 이름이 찍힌 종이가 나온다.

## 한 일

- 훅이 Write 결과의 `type` 을 본다. Claude Code 는 새 파일이면 `"create"`, 덮어쓰면 `"update"` 를 준다. `"create"` 일 때만 `file_created` 를 보낸다(`hooks/src/claude_office_hooks/event_mapper.py`).
- 백엔드가 `file_created` 를 저장하고, 기록 상세에 `fileCreated` 로 싣는다. 백엔드를 다시 띄워 기록을 되살려도 남는다(`backend/app/models/events.py` · `core/event_processor.py`).
- 개발실 뒤 오른쪽, 벽시계 아래 엘리베이터 옆에 받침대 위 프린터를 둔다(x 25.9 · z 0.75). 길찾기는 그 자리를 피한다(`isoFloorPlan.ts` · `isoFurniture.ts`).
- 세션의 새 파일마다 프린터 위 칸에 종이가 한 장씩 쌓인다(6장까지). 1분 안에 들어온 새 파일은 앞판 램프가 초록으로 깜빡이고, 종이가 뒤쪽 슬롯에서 2.4초 동안 나와 위 칸에 놓이며, 「🖨️ 파일 이름」 이름표가 프린터 왼쪽 위에 5초 동안 뜬다(벽시계를 가리지 않게). 한꺼번에 들어오면 3개까지 차례로 찍는다(`systems/officePrinter.ts` · `components/iso/isoPrinter.ts`). 공항 · 건설 현장 · 낚시터에는 없다.
- 시험: 훅의 create · update · 응답 없음(`hooks/tests/test_event_mapper.py`), 백엔드 재시작 뒤 `fileCreated`(`backend/tests/test_event_restore.py`), 파일 이름 · 새 파일 고르기 · 1분 규칙 · 진행률(`frontend/tests/officePrinter.test.ts`).

## 검증하지 못한 것

- 실제 Claude Code 세션의 Write 는 보내지 않았다. 훅 출력은 시험으로, 화면은 같은 이벤트를 API 로 넣어 봤다. 이미 설치된 훅은 다시 설치(`hooks/install.sh`)해야 `file_created` 를 보낸다.
- 위 칸의 종이는 장마다 4mm 라서, 기본 배율에서는 한 장과 여러 장이 거의 같아 보인다. 크게 확대하면 비뚤게 쌓인 가장자리가 보인다.
